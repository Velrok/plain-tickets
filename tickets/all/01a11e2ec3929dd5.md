created_at and updated_at are bare u64 epoch seconds (domain/tickets.rs); main stores ISO 8601 (2026-04-30T19:00:00Z). Epoch seconds are unreadable in the files and in 'show'.

Acceptance:
- Add a Timestamp newtype that serialises to and deserialises from RFC 3339 UTC (second precision), with a unit test round-trip.
- Replace the u64 fields and the now() helper in handlers.rs with it; Ticket::new/revise take a Timestamp.
- Reject malformed timestamps with a clear error.
- Update pretty/plain presenters and the README format notes.
- Decide whether to read old epoch values (migration) or reject them.

Update: Timestamp must keep millisecond precision (e.g. 2026-04-30T19:00:00.123Z). list orders by created_at, and the random-ID ticket removes the time-sorted ID that ce0e286 used as the same-second tie-break.
